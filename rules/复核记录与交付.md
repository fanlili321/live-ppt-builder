# 交付流程与复核记录

按环节归类（2026-11-23 重整）。以后新增规则直接放进对应环节或「通用」小节，不再按期数往文末追加。

## 总览
| 环节 | 谁 | 做什么 |
|---|---|---|
| 1 | AI | 读大纲 → 出初稿 → 自查 + `ppt-review` 复核 → 交给用户 |
| 2 | 用户 | 用户修改 → AI 比对改动 + `ppt-review` 复核 → 上传 iCloud 在线文档 → 机器人发 PPT 制作群 @汤爱学 |
| 3 | 汤爱学（可多轮） | 按反馈改在线文档 → 只复核改动页 → 汤说没问题即结束 |
| 4 | 王磊（可多轮） | 整份终审 → 导出 PDF → 机器人发 226课程群 @王磊 → 按反馈改 → 只复核改动页 → 再发 PDF → 王磊确认 = 定稿 |
| 定稿后 | AI | `live-ppt-publisher` 发布 → 定稿后反馈收集 → 清理中间文件 |

**版本（2026-11-23 用户定，简化）**：本地只有 `NNN期_主题_v1_claude输出.key`（AI 初稿，用作比对用户改动的基准）。用户改好的文件上传成 iCloud 在线文档后，**在线文档就是唯一的正式版本**，之后不再另存 v2、v3 等本地版本。本地只留两样：每次动在线文档前的「改前备份」，和每轮发给王磊的 PDF。每次改动都和上一版逐页比对（`keynote_tool.py verify` + 导出页图对比 + `charts/get` 对数据；在线文档用改前备份作上一版）。

**复核范围（2026-11-23 用户定）**：整份 `ppt-review` 复核在环节 1、环节 2 各做一次；整份终审数据核对只在第一次提交王磊前做一次。环节 3、4 每轮修改后，只复核**改动页 + 引用同一数字的页 + 总结页**。

## 环节 1：AI 初稿 → 用户（重在过程）
交付（不出 PDF）：
1. **v1 `.key`** 路径。
2. **过程记录**（按页，写进飞书「PPT制作过程记录」，写法见文末）：
   - 操作：复制自哪期哪页 / 新画；删、移了哪些页；改了哪些文字、表格、标注；哪些图换了数据（slide 文件、行数、区间）。
   - **四点核对**（老板要求，每张走势图）：| 页码 | 线 | 开始 | 结束 | 最高 | 最低 | 权威源对照值 | 一致 |。
   - 数据处理：每条线 | 页码 | 图上名称 | 代码 | 价格/全收益 | 来源（Wind/数据工具箱/人工提需/其他）| 频率 | 区间 | 价格口径 | 与历史比对 |；指标怎么算（回撤峰谷、涨幅高低点、年化、比值、换算汇率）；补点、沿用前值、两标的对齐方式。
   - `ppt-review` 的逐页复核表（写进过程记录本期小节，不另写「PPT复核问题记录」）。
3. **待确认清单**（单独列）：与历史不吻合项、待补数据（已写 PPT数据提需）、待更新截图、我自己做的判断。

### 用户改过文件之后（486 期经验）
- 先查文件是否开着、`modified` 是否为 false，再导出页图和我上一版**逐页像素比对**，列出用户改了哪几页、改成了什么；再读批注（批注文字在 `Slide-*.iwa` 里，比对新增中文字符串）。用户的改法就是新的样式依据（如 P6–P8 外框只改颜色粗细、保留阴影 → 其他框照做）。
- **每次动手前留 `data/改前备份_xxx.key`**。用户说「不要改了」时，直接用改前备份整份还原并 verify（不要逐项手工撤销）。
- 发现与大纲不一致、或一处有多种合理改法时，先问；用户确认的结论写进过程记录的待确认清单（写明日期，不删）。

## 环节 3：汤爱学复核 → 修改（可多轮）
1. 汤爱学的反馈逐条记入**反馈落实表**：| 轮次 | 序号 | 反馈原文 | 页码 | 改前 | 改后 | 连带修改 | 状态 |。
2. 每改一处检查连带：同一指标其他页、总结页、正文与图上标注、页序/页码；数据改动重新取数 + 历史比对。
3. 直接更新在线文档（优先原地改，见「通用：改在线文档」）；改完跑 `ppt-review`，**只复核改动页 + 引用同一数字的页 + 总结页**。
4. 数据有改动的，同步更新「PPT数据复核」对应行和截图。
5. 汤爱学说没问题即结束；可能不止一轮，每轮在过程记录里追加「修改记录 汤爱学第 N 轮」。
6. **领导请假可跳过本环节**：用户明确说跳过时，上传在线文档后直接进入环节 4。

## 环节 4：提交王磊（226课程群，PDF）→ 按反馈修改（可多轮）

### 4.1 首次提交前：整份终审数据核对（只做这一次，结果先发用户）
- 每个数字从数据源重新取、重新算并逐个对照；跨页一致；无缺图、截图最新；「PPT数据复核」与当前在线文档逐项一致。
- **原样复用的历史页，数字也要重算**：487 期 P21（沿用 482 期）图例写「沪深300全收益」，最大回撤 -72.3% 却是价格指数口径（全收益 -72.04%）。终审脚本要覆盖所有带数字的页，不只换过数据的页；发现不一致报给用户定，用户说不改就在数据复核里如实注明口径。
- 终审脚本模板：`scripts/final_audit_例487.py`（工具箱重取 → 与 `keynote_tool get` 读出的在线文档图表逐点对照 → 重算表格/标注），再用 `scripts/wind_spotcheck.py` 换 Wind 独立核对（见「通用：终审用独立来源复核」）。

### 4.2 导出 PDF、发课程群
1. **从在线文档导出 PDF**：在线文档在 Keynote 里开着时 `export d to POSIX file ".../output/NNN_claude输出/pdf/<PPT标题>.pdf" as PDF`（只导出，不改不存在线文档）；文件名 = PPT 标题（同 iCloud 在线文档名）。导出后核对 PDF 页数 = 在线文档可见页数，抽看封面和最后一页。每轮导出的 PDF 都留在 `pdf/` 下（文件名后加 `_第N轮` 区分，发群时用不带后缀的标题名），王磊按这份的页码反馈。
2. **先给用户看待发内容，用户说「发」后再发**。用直播小助理机器人发到 226课程群（`oc_ad278b7a15d31ab7a5ced19569769db8`），身份要求同 `live-ppt-publisher` 第四步：显式 `--profile live-poster-bot`，校验 App ID `cli_a94b5144b1381cb3`，不用范丽丽个人身份。
   - **王磊的 open_id 用 live-poster-bot 档案解析**（open_id 按应用不同，用户身份查到的 ID 不能直接用），方法同 `live-ppt-publisher`「open_id 按应用保存」；解析结果记下来复用。
   - 先发 PDF：`lark-cli --profile live-poster-bot im +messages-send --as bot --chat-id oc_ad278b7a15d31ab7a5ced19569769db8 --file <相对路径>.pdf`
   - 再发 post @王磊。首次话术：「{今晚/明晚}直播ppt如下，辛苦钉大反馈下哈\n附：https://epndqwwg0a.feishu.cn/wiki/NN4uwNq6riHMxvkNDGxcz86HnNg」（直播当天写「今晚」，前一天写「明晚」）。
   - 发完读回核对 sender 是 `cli_a94b5144b1381cb3`、chat_id、文件名、mentions 含王磊；记下两条 message_id。

### 4.3 王磊反馈 → 修改（可多轮）
1. 页码对照：王磊说的页码 = 发给他的那份 PDF 的页码。先列「反馈页码 → 在线文档页（用页标题确认）」对照，再动手。
2. 反馈记入同一张反馈落实表（轮次写「王磊第 N 轮」）；改法、连带检查、原地改在线文档同环节 3；`ppt-review` 只复核改动页 + 引用同一数字的页 + 总结页。
3. 改到数据的页，对改动页和引用同一数字的页重做终审核对（不再整份终审）；同步「PPT数据复核」。
4. 改完重新导出 PDF（4.2 第 1 步），用户确认后机器人发课程群：先发新 PDF，再发 @王磊「{今晚/明晚}ppt已按反馈调整，辛苦钉大再确认下哈」。
5. 王磊确认、用户说定稿 = 定稿，转 `live-ppt-publisher` 发布；之后做定稿后反馈收集和清理。

## 定稿后

### 定稿后又来了老板反馈（486 期 2026-11-13 实测流程）
定稿后在线文档默认不动（安全铁律第 15 条）。只有用户明确说「改本地、我确认后再替换到在线文档」时，按下面做：
1. **本地副本**：`cp -R` 复制在线文档到 `output/NNN_claude输出/wl/`，复制前后核对在线文档修改时间不变；所有修改只在这份上做。
2. **页码对照**：王磊/汤爱学说的页码是他们看到的 PDF 或在线页码（= 可见页码，不含隐藏页）。保留发给他们的那份 PDF（如 `wl/wl_sent.pdf`），先列「反馈页码 → 本地 slide 序号」对照表再动手。
3. **数据页和非数据页分开**：缺数据的页先提需（写明期望交付时间，如「直播当天 14:00 前」），其余页先改；用户确认后**先替换非数据页**，数据到了、用户确认数据后**再替换数据页**。
4. **每次替换前**：在线文档 `cp -R` 留快照（`wl/在线文档_xxx替换前快照_MMDD.key`）；源页放 `tmp/` 的临时副本里。**用户的便签/批注一律不用管，留着即可**（不删、不清空，上传和替换在线文档时也照原样带上；2026-11-19 用户定）。
5. **替换**：`scripts/replace_slides_online.py`，每步校验，失败即停（注意事项见「通用：改在线文档」）。
6. **替换后**：在线文档与源副本都导出页图，逐页像素比对。除了替换的页，**在线文档里原来就有、本地没有的差异**（486 期：第 4 页标题被改成「z」、第 24 页多一条要点）一律不动，列出来告诉用户。
7. 在过程记录该期小节追加「修改记录（反馈/替换在线文档）」。

### 定稿后清理中间文件（2026-11-12 用户定，防止占满磁盘）
- **时机**：这一期定稿（环节 4 王磊确认，或用户说「定稿了」「直播结束」）、定稿后反馈收集做完后，默认清理，不用再问；做完告诉用户清了哪些、腾出多少空间。
- **做法**：`python3 scripts/cleanup_episode.py output/NNN_claude输出` 先列清单和大小，确认无误后加 `--apply`。一律**移到废纸篓**（可在访达「放回原处」），**不清空废纸篓、不用 rm 永久删除**。
- **原则：非必要不保留，能删的尽量删**（2026-11-13 用户定）。过程记录在飞书、定稿由用户上传飞书存档、原始数据在「PPT数据提需」/工具箱可重取，所以定稿后**整期文件夹 `output/NNN_claude输出/` 一起移到废纸篓**。
- 删之前只做一件事：这一期写的脚本里**以后还会用的**，先并入 skill 的 `scripts/`（如 486 期的 `bull_bear_phases.py`、`md2docxml.py`、`replace_slides_online.py`），并更新引用它的规则。
- `cleanup_episode.py` 适合定稿前清中间文件；定稿后直接整夹移废纸篓。
- 旧的保留清单（已废止）：过程记录、scripts/、data/。
- **清理**：所有「改前备份」、tmp/、src/（历史期 .key 复制件，缓存里还有）、export*/ 和 review/ 的页图与副本、outline/img/、pdf/、v1 等 .key。
- **不碰**：iCloud 在线文档（**定稿后在线文档一律不动**，见安全铁律第 15 条）、用户自己的文件、Keynote 正开着的文件（脚本检测到会跳过）。
- **不留在线文档的本地副本**（2026-11-13 用户定）：定稿由用户自己上传飞书存档，清理时**不再从在线文档复制快照**，本地所有 .key（v1、在线快照、改前备份）都移到废纸篓。在线文档本身一律不动。
- `history_keys/` 缓存（历史期 .key，下期还会复用）不自动清；超过约 300MB 时，列出最久没用的几期问用户是否移到废纸篓。
- 486 期实测：中间文件约 787MB，其中改前备份约 145MB、tmp 215MB、src 156MB、页图约 200MB；定稿后可腾出约 764MB。

## 通用：改在线文档

### 协作格式（486 期实测）
- 在线文档开启协作后，Keynote 会转成协作格式（文件夹包 + ActivityStream/OperationStorage），**不能再直接改文件内部**。以线上为准：每次修改前把线上 `cp -R` 留一份「改前备份」，试改在这份副本上做，确认效果后再改线上（不另存 v2、v3 版本）；改完与本地逐页像素比对，差异列出问用户。
- 原地改不了、只能整页替换时：本地副本做好整页，用 `scripts/replace_slides_online.py`（逐页粘贴、等 3 秒、签名校验、移位、删旧页）拷进在线文档；替换前后核对页数和页面内容（用户可能同时在改），对不上立刻停手问用户。
  - 脚本用标题+文字签名区分新旧页；只有图表/表格不同、或只改了位置/颜色/图片的页会报「新旧页无法区分」：用 `i:源页:旧页` 插入，再用表头、位置、图片文件名等确认旧页后手动删除。连续插入时后面的页号会 +1，一次只做一页或按新页号写。
  - **换过图片的页（488 期实测）**：协作文档粘贴时按**图片文件名**复用文档里已有的同名图片，包内直接替换的新图会显示成旧图。替换前在源副本里把新图用**新文件名**重新插入（同位置同尺寸，删旧图；原有边框用 `set_image_borders.py --only` 补回），粘贴后像素比对确认。

### 保留领导批注（488 期教训，2026-11-19 用户定）
- 488 期按汤爱学批注改了 8 页后整页替换，**旧页上的批注跟着被删了**。领导的批注要留在在线文档上，下次按下面做：
1. **优先在线上原地改，不整页替换**：在线文档在 Keynote 里打开时，可以用 AppleScript 直接改（移动文字框、改文字、改颜色、插图删图），界面操作（如 `gui_align_left.js`）也可以直接做，批注都保留。改之前先在本地副本上试同样的脚本、导出页图确认效果，再对在线文档执行同一脚本；改完导出在线页图和本地副本像素比对。
   - 换图片：在线页上 `make new image`（**用新文件名**，同位置同尺寸）→ 删旧图 → 原有边框只能界面补或接受无边框，先问用户；不要往在线文档包里 zip 替换文件。
   - **489 期实测可行**（2026-11-23）：协作在线文档在 Keynote 里开着，AppleScript `set position of shape k of slide n` + `save d`，P22 两个红点原地移动；改后元素数不变、领导便签保留，在线页图与本地试改版像素差 0。
   - **换截图也能原地做**（489 期 P13 实测）：`set file name of image k of slide n of d to POSIX file "新图.png"`，位置、尺寸、#FEAD00 边框都保留，不用删图重插、不用改 iwa。新图宽高比要和旧图一致（不一致先裁）。
   - 加红字等新文字框：`tell s to make new text item with properties {object text:"待更新截图", position:{x, 1500}, width:260, height:60}`，再按文字内容找到它设字号、颜色、位置（`make new text item at end of text items` 写法会报 -10000）。
   - **协作文档里不要用 AppleScript `delete shape`**（489 期实测）：删除会落到序号错一位的另一个对象上（误删过另一个 ▶ 和一个隐藏形状）。要去掉的形状改为挪到页面外 `{300, 1400}`（模板隐藏形状同处，放映、导出都看不到）。整页新增用 `duplicate slide k of d to after slide k of d`（可靠）。
   - AppleScript `make new …` 后不能用「最后一个 text item / image」定位新对象（会改到隐藏占位文本框），一律按文件名或文字内容定位。
   - 补 ▶ 等形状：`scripts/gui_paste_shape.js`；Keynote 窗口在外接屏时坐标为负，先 `screencapture -x a.png b.png` 截两块屏量画布左上角和缩放。
2. **只有原地改不了时才整页替换**（例如整页重排版、大量元素变化），替换前先告诉用户「这几页的批注会被删掉」，用户同意后再做；并把旧页上的**便签形状**（批注多数是带文字的便签形状，AppleScript 能列出文字）用界面复制粘贴到新页同一位置，替换后核对便签数量和文字与替换前一致。
3. Keynote 自带的「评论」（AppleScript 列不出、只在 Slide-*.iwa 里有文字，如 488 期 P18 那条）无法复制，整页替换必然丢失：替换前把评论原文记进过程记录，并告诉用户。
4. 每次动在线文档前都要用户明确同意；用户说「不要动在线文档」时，只在本地改好、告诉用户改了哪些页，由用户自己在线上改。
- 读批注：`scripts/slide_strings.py 本地版.key 在线文档.key`（包格式直接传文件夹，只读）找出新增文字，再用 AppleScript 列出每页带文字的 shape 区分「便签形状」和「评论」。

## 通用：多页统一成同一版式（用户说「和第 X 页改成一样」）
- 先在参考页量出全部参数：正文框 x/y/宽、字号、行距（段落样式 12.13）、文本框内边距（形状样式）、▶ 位置、图例位置（图表字段 10000.3，见 `keynote环境与能力边界.md`）、日期和来源位置。
- 逐页套用后导出页图，用像素量：首行顶部、▶ 中心、图例左缘、文字右缘，与参考页逐项对比（差 ≤1px）。文字超出右边界的加软换行（`character id 8232`），不缩字号。

## 通用：终审用独立来源复核（2026-11-16 用户定）
- **作图用工具箱，复核必须换一个来源**：工具箱指数行情后台也是 Wind，同一通道既作图又复核，通道本身的错（缺行、错位、异常值）查不出来。
- 指数行情复核走 **Wind MCP `index_data get_index_kline`**（`aftype:"2"` 不复权，日K，每条线一次调用即返回整段序列，2004 年起 5000+ 行也能一次取回）。用 `scripts/wind_spotcheck.py lines.json` 与工具箱逐日比对，并核四点（起/末/高/低）和最大回撤峰谷。487 期 12 条线约 12 次调用。
