# Wind API 使用规则与任务前置沟通习惯

## Wind MCP API 硬性限制（必须在任务开始前主动告知用户）

- 每次查询最多返回 **100条**，无法绕过
- 成分股数量 ≥ 1000 的指数（中证1000、中证2000等），调仓变动几乎必然超过100条
- **必须在接到任务时主动说**："XX指数成分股超1000只，调仓数据可能超过API上限，建议您提前从Wind终端导出备用"

## 查询调仓数据的正确流程

1. 接到任务 → 先识别哪些指数会触发截断限制，**一次性告知用户**
2. 每个指数固定分两次独立查询：纳入 / 剔除分开问（合并问容易只返回一种）
3. 查完核对：`excelTotalCount ÷ 列数 = 理论行数`，与实际返回行数对比，不一致立即告知
4. 写文件前先汇总所有指数的调入/调出数量，展示给用户确认，用户点头后再保存
5. 禁用 `analytics_data` 做精确指数成分查询（容易串数据，如300成长调出事故）

## 任务前置沟通原则（通用）

**在执行前把已知的障碍、风险、需要用户配合的点一次性说清楚**，而不是撞墙后再回来找用户。

具体包括：
- 涉及大数据量 → 提前说明限制，建议用户准备导出文件
- 涉及格式/风格参考 → 主动问清楚指的是哪个项目/文件路径，不要自己猜
- 涉及第三方权限（飞书写入等）→ 先确认权限是否具备，再动手
- 复杂任务 → 建议分步验证（小范围先跑通，再全量）

## 指数K线/收盘价导出规则（2026-06-08）

### 全收益指数代码规则
- 沪深300全收益：`H00300.CSI`（不是 H000300.CSI）
- 中证全指全收益：`H00985.CSI`（不是 H000985.CSI）
- 规律：全收益代码 = `H` + 去掉首位0的原代码 + `.CSI`，需向用户确认，不得自行假设

### 指数基准日与回算数据陷阱
- 沪深300（000300.SH）正式发布日：2005-04-08，基准日：2004-12-31
- Wind 对000300.SH 提供回溯至2002年的**反推/模拟数据**，非真实发布数据
- **必须在查询前先用 `get_index_basicinfo` 确认基准日**，以两个指数共同最早真实日期为起点，不得用19900101盲查
- 全收益指数（H00300.CSI等）通常从基准日（2004-12-31）起算，与价格指数对齐

### 多指数周频导出规则
- 周频 = 每周取最晚不超过周五的最近交易日，且两个指数当天都必须有数据
- 代码结构：存入字典时用 `seen[date_key] = (v1, v2)`，遍历时用 `for date_key, (v1, v2) in final_rows`，不得错误地三元解包
- 导出前必须断言无缺失：`assert v1 is not None and v2 is not None`

## 本次教训（2026-06-05 指数调仓任务）

- 中证2000：API只返回100条，误当完整数据使用，实际有182条，靠用户手动导出补全
- 300成长调出：用了 `analytics_data` 而非 `index_data.get_index_fundamentals`，后半段串入了沪深300的数据，前10条正确后9条全错，靠交叉核对才发现
- 飞书文档写入：App权限不足导致全部失败，应提前确认权限
- 多次生成错误版本（v1→v2→v3→v4），根本原因是没有在开始时做数据量预检和用户确认
