# Keynote自动化 安全铁律（2026-07-29 误删用户原稿事故后）
1. **绝不用 `front document`**。一律 `set d to (open POSIX file "...")` 直接拿引用，或按**完整文件路径/唯一文件名**锁定；找不到就 error 中止，**绝不退回操作别的文档**。
2. 我输出的本地文件名**必须带 `claude输出`**，和人工/别的AI的稿区分，别用雷同命名。**例外：上传到 iCloud 的在线文档直接用 PPT 标题命名**（见 `复核记录与交付.md` 环节 2）。
3. 动手前 `count of documents` 列出已打开文档；**用户打开着的文件绝不碰**；在**隔离副本**上做。
4. **不写盲批量 `delete slide`**；删除前核验页数，不符即中止。
5. 出错(-1719/-609/-1712)不要盲目重试变更操作（可能已部分执行→叠加）；先查状态。
6. Keynote 自动化前先 `open -a` 启动；osascript 包 `with timeout of 600 seconds`。
7. 交付前逐页导PDF自检；成品只给 .key。

事故复盘：用 front document + `delete slide 1` 循环删模板页，结果删到了用户同时开着的人工原稿，autosave 把损坏写回iCloud。→ 上面每条都是为堵这个。

## 8–12（2026-11-09，485 期补充）
8. **改 .key 包内文件只能用 `zip` 命令行逐条替换**（`scripts/keynote_iwa/keynote_tool.py` 已封装）。**禁止用 Python zipfile 整包重打**：Keynote 的中文文件名（「图层 1」「已粘贴的图像」「截屏…」）不带 UTF-8 标记，重打会写成乱码 → Keynote 找不到图片 → 页面空白；用户再保存时 Keynote 会把这些图**永久删掉**（485 期封面、P11、P24 因此丢图，靠备份恢复）。
9. 每次改完跑 `keynote_tool.py verify 改前.key 改后.key`：只允许出现计划内的条目变化；「被引用但缺失的图片」必须为「无」。丢图用 `keynote_tool.py restore --from 备份.key` 补回。
10. 动用户文件前：`modified of document` 为 true（有未保存修改）就停下请用户先保存；为 false 才可关闭→改→重新打开。改前在同目录留 `-改前备份` 副本；定稿后按 `复核记录与交付.md`「定稿后清理中间文件」统一移到废纸篓。
11. `.key` 有两种格式：单文件（zip）和包格式（文件夹，内含 `Index.zip` + `Data/`，iCloud 上常见）。工具两种都支持；复制包格式用 `cp -R`。
12. 用户可能随时移动/改名文件：每次动手前用 `POSIX path of (file of document …)` 或用户给的路径重新确认，不凭记忆。
13. **替换文件的前一刻再查一次**：① 原文件和改前副本是否一致（iCloud 可能在复制后同步进新版本，485 期就发生过：P17/P23 星级图在复制后被更新）——不一致就在最新版本上重做；② 该文件在 Keynote 里是否开着。开着且未修改：替换后**关闭再重新打开**，否则 Keynote 内存里还是旧版，一保存就把新文件覆盖回去；开着且有未保存修改：停下来请用户先保存。
14. 替换包格式 .key 用「原文件移到备份位置 → 新文件移到原路径」，不要在原路径上原地改。

## 15. 定稿后绝不动在线文档（2026-11-12 用户反复强调）
- 用户说「定稿了」之后，**iCloud 在线文档（及其共享链接）一律不动**：不打开、不改、不重命名、不替换页面、不改共享设置、不移动/删除。用户自己会继续在线上改。
- 定稿后只允许**读**：如需本地留档，只用 `cp -R` 复制到 `output/NNN_claude输出/`，复制前后核对在线文档的修改时间不变。

- 定稿前要改在线文档，也只能在用户明确要求时做，并按「整页替换」流程（`复核记录与交付.md`）。
